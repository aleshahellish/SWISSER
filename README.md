# SWISSER

SWISSER получает закрытые свечи MEXC Futures и строит структурированные данные
для двухэтапной проверки:

1. `/api/scanner_action_v6` — общий shortlist.
2. `/api/snapshot_action_v6?symbol=HYPE_USDT` — подробная проверка кандидата.

`/mcp` предоставляет ChatGPT freshness-gate, scanner, пакет подробных snapshots,
панель команд и отдельный renderer рыночной карточки SWISSER. Кнопки отправляют
полный запрос в текущий чат. Панель автоматически запрашивает компактный
PiP-режим на время активной сессии. После переключения на другой чат ChatGPT
может завершить PiP, поэтому три команды также показываются под каждой новой
рыночной карточкой — прокручивать разговор к первой панели не требуется.
Ручная кнопка закрепления сохранена как резервный вариант. Интерфейс панели
монохромный и компактный. Три кнопки образуют последовательный рабочий процесс:

1. `Обзор рынка` — нейтральный scanner всех шести торговых монет без рейтинга
   и принудительного выбора.
2. `Лучшие сетапы` — scanner и snapshot всех действительно конкурентных
   кандидатов без заранее заданного количества. Равноценные монеты остаются в
   одном top-tier без искусственного победителя; качество сетапа и готовность
   входа оцениваются отдельно.
3. `Проверить вход` — повторная проверка только списка из последнего результата
   `Лучшие сетапы`: свежая значимая 1m CHoCH-цепочка, возможный последующий
   BOS, displacement, откат/ретест, опоздание и инвалидация. C2/C3 остаются
   дополнительным контекстом, но не обязательным триггером и не veto. Новые
   монеты в этом режиме не добавляются.

Если второго результата в текущем диалоге ещё нет, третья команда просит сначала
сформировать список кандидатов. Если все сохранённые сценарии отменены, новый
отбор снова запускается второй командой.

Scanner сам создаёт новый запуск и возвращает один подписанный `evidence_token`.
В режимах `setups` и `entry` все выбранные snapshots запрашиваются одним пакетным
вызовом, после чего прежний токен заменяется одним новым атомарным токеном,
содержащим scanner и весь пакет. Поэтому модель больше не переносит отдельные
`run`, `scan` и snapshot-токены и не может случайно собрать карточку из разных
запусков. Evidence действует пять минут от scanner. Snapshot старше scanner,
неполный набор `entry`, добавленная монета или повреждённая подпись жёстко
отклоняются. При технической ошибке допускается только один чистый повтор.
`render_swisser_market_card` не запрашивает рынок повторно,
но строит цену, 4h/1h/15m/1m, активную идею, BTC и время среза только из
проверенного evidence — модель не может подменить эти поля вручную. В режимах 1–2 верхняя таблица
показывает все шесть монет, а в режиме 3 — только ранее отобранных кандидатов.
Нижняя таблица появляется для реальных кандидатов в режимах 2–3. Равные уровни
приоритета получают одинаковый цвет вместо принудительных мест 1–3. Колонки,
компактность, Italianno и приглушённые Bull/Bear сохранены; RR не выводится. Под итогом карточки
повторяются три рабочие команды без нового вызова Work.
Карточка занимает всю доступную ширину, переносит длинные цели и PnL внутри
ячеек и сообщает ChatGPT свою фактическую высоту, поэтому отдельные
горизонтальная и вертикальная полосы прокрутки внутри неё не требуются.

Рыночная логика сосредоточена в двух активных Python endpoint; старые дублирующие
endpoint, GPT Action schema, отдельная TAO-страница и инструкция Analyst удалены.
Прежние URI MCP-карточек сохранены только для чтения уже созданных сообщений и
предотвращения `Failed to fetch template`.

## Что изменено

- Единственным источником BOS/CHoCH стала открытая логика
  `Smart Money Concepts [LuxAlgo]`: internal 5 — рабочая структура ТФ,
  swing 50 — стратегический контекст.
- Legacy confirmed-fractal 2/2, его BOS/CHoCH, protected levels, CISD и
  swing-последовательности исключены из активных API и MTF. Они остаются
  только в истории Git для возможного отката.
- При конфликте Lux swing/internal API передаёт оба слоя и не позволяет
  локальному событию молча переписать масштаб структуры.
- Рабочий сценарий теперь определяется ядром `1h → 15m → 1m`. `4h` остаётся
  стратегическим контекстом и не может превратить продолжающийся 1m-откат в
  активный LONG/SHORT. Совпавшие против 1h направления 15m+1m выделяются
  отдельно как `LOCAL LONG`/`LOCAL SHORT`, а не как разворот всей структуры.
- Поле `continuation_bias` описывает идею продолжения, а
  `active_trade_scenario` — текущую сделку или `WAIT`.
- Готовность входа теперь определяется свежей LuxAlgo internal 1m
  CHoCH-цепочкой. Последующий BOS сохраняет подтверждение, если относится к
  той же структурной ноге. Свежий C2/C3 больше не является обязательным
  пропуском и не может отменить структурно подтверждённый вход.

- C2 требует sweep одной стороны C1 и close обратно строго внутри диапазона C1.
- Цвет C1 больше не является условием.
- Reversal Filter 12 применяется отдельно к bullish и bearish экстремумам.
- Двусторонняя C2 может вернуть две метки одного времени.
- Sweep с закрытием за противоположной стороной C1 вынесен в
  `SWEEP_PLUS_OPPOSITE_EXPANSION`, а не называется C2.
- Wick Threshold 40% выбирает основу EQ: rejection wick либо полный диапазон.
- C3 фиксируется по close за диапазоном C2; `eq_respected` хранится отдельно
  как качество.
- Добавлены фазы C2, C3, C4, C5 и предупреждение о свежей противоположной H1
  Closure.
- BTC остаётся в сканировании как `MARKET_CONTEXT`, но получает
  `eligible_trade_candidate: false`.
- Ответы двух GPT Action endpoint имеют жёсткую проверку лимита в 100 000
  символов. Нагрузочный тест требует запас не менее 20% и сохраняет все
  внутренние расчёты, сокращая только дубли и историю однотипных событий.

Структурная часть является чистой Python-реализацией правил официального
открытого Pine-кода LuxAlgo SMC v7 с настройками пользователя. TTrades/C2/C3
остаётся отдельной логикой фаз свечей и подтверждения, а не вторым источником
BOS/CHoCH. API остаётся shortlist и источником фактов; POI/FVG/OB и финальный
вход проверяются отдельно.

## Проверка

```bash
python3 -m py_compile candle_closure.py api/*.py
python3 -m unittest discover -s tests -v
npm run test:mcp
```

Внутренние endpoint сохраняют полный проверяемый набор данных, но MCP передаёт
модели только необходимую аналитическую выжимку. Это уменьшает контекст и не
заставляет модель переносить токены после ответов размером около 80 КБ.

## Активные Vercel Functions

- `api/health.py`
- `api/scanner_action_v6.py`
- `api/snapshot_action_v6.py`
- `api/mcp.js` (`/mcp` через rewrite)

Модули `candle_closure.py`, `luxalgo_structure.py`, `mtf_decision.py`,
`swisser_evidence.js` (provenance/freshness gate) и `swisser_market_card.js`
лежат в корне и не создают отдельных функций. Откат выполняется через историю Git; дополнительная
страховочная ветка `stable-v1` сохранена отдельно от production-ветки `main`.
